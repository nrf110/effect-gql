The `GraphQLSchemaBuilder` is an immutable, pipeable builder for constructing GraphQL schemas. It accumulates type definitions and resolver registrations, then builds a standard `GraphQLSchema`.

## Import

```typescript
import { GraphQLSchemaBuilder } from "@effect-gql/core"
```

## Creating a Builder

### `GraphQLSchemaBuilder.empty`

Creates a new empty schema builder.

```typescript
const builder = GraphQLSchemaBuilder.empty
// Type: GraphQLSchemaBuilder<never>
```

The type parameter `R` tracks accumulated resolver and argument-decoder service requirements.

## Root Operation Methods

### `query(name, config)`

Register a Query field.

```typescript
builder.query("users", {
  type: S.Array(UserSchema),
  args: S.Struct({ limit: S.optional(S.Int) }),
  description: "Get users",
  resolve: ({ limit }) => Effect.succeed(users.slice(0, limit)),
})
```

**Parameters:**

| Name | Type | Description |
|------|------|-------------|
| `name` | `string` | Field name |
| `config.type` | `Schema<A>` | Return type schema |
| `config.args` | `S.Decoder<Args, RArgs>` | Optional whole-argument decoder, normally `S.Struct({...})`; resolvers receive decoded values |
| `config.description` | `string` | Optional field description |
| `config.resolve` | `(args) => Effect<A, E, R>` | Resolver function |

**Returns:** `GraphQLSchemaBuilder<R | R2 | RArgs>` (adds resolver and decoder services).
Fields without an argument schema receive `void`. Query fields additionally
support `directives`, `complexity`, and `cacheControl`; mutations support
`directives` and `complexity` but not `cacheControl`.

### `mutation(name, config)`

Register a Mutation field. Same signature as `query()`.

```typescript
builder.mutation("createUser", {
  type: UserSchema,
  args: S.Struct({ name: S.String, email: S.String }),
  resolve: ({ name, email }) => Effect.gen(function* () {
    const db = yield* Database
    return yield* db.createUser({ name, email })
  })
})
```

### `subscription(name, config)`

Register a Subscription field. `subscribe(args)` sets up the stream; optional
`resolve(value, args)` runs an Effect for each event.

```typescript
builder.subscription("messageAdded", {
  type: MessageSchema,
  args: S.Struct({ channelId: S.String }),
  subscribe: ({ channelId }) => Effect.gen(function* () {
    const pubsub = yield* PubSubService
    return pubsub.subscribe(`channel:${channelId}`)
  }),
  resolve: (message, _args) => Effect.succeed(message),
})
```

`subscribe` returns `Effect<Stream<A, E, R2>, E, R2>`; optional `resolve` returns
`Effect<A, E, R2>`. Both receive the same arguments decoded once at operation setup.
The returned builder accumulates `R2 | RArgs` along with its existing services.

## Type Registration Methods

### `objectType(config)`

Register a GraphQL Object type.

```typescript
builder.objectType({
  name: "User",           // Required for plain structs
  schema: UserSchema,
  description: "A user"
})

// Name is optional for TaggedStruct/TaggedClass/Class
builder.objectType({
  schema: S.TaggedStruct("User", { id: S.String, name: S.String })
})
```

**Type Name Inference:**
- `S.TaggedStruct("Name", {...})` → Name extracted from tag
- `S.TaggedClass("Name")` → Name extracted from tag
- `S.Class("Name")` → Name extracted from class
- Unannotated `S.Struct({...})` → Requires an explicit `name`; identifier annotations can also provide an inferred name

### `interfaceType(config)`

Register a GraphQL Interface type.

```typescript
builder.interfaceType({
  name: "Node",
  schema: NodeSchema
})
```

### `unionType(config)`

Register a GraphQL Union type.

```typescript
builder.unionType({
  name: "SearchResult",
  types: ["User", "Post", "Comment"],
  resolveType: (value) => {
    // Return the type name based on the value
    if ("email" in value) return "User"
    if ("title" in value) return "Post"
    return "Comment"
  }
})
```

### `enumType(config)`

Register a GraphQL Enum type.

```typescript
builder.enumType({
  name: "Status",
  values: ["ACTIVE", "INACTIVE", "PENDING"],
  description: "Account status"
})
```

`values` is a readonly array of strings. Per-value description/configuration
objects are not supported.

### `inputType(config)`

Register a GraphQL Input type for complex arguments.

```typescript
builder.inputType({
  name: "CreateUserInput",
  schema: CreateUserInputSchema,
  description: "New user details"
})
```

## Field Methods

### `field(typeName, fieldName, config)`

Add a computed or relational field to an object type.

```typescript
builder.field("User", "posts", {
  type: S.Array(PostSchema),
  args: S.Struct({ limit: S.optional(S.Number) }),
  description: "Posts by this user",
  resolve: (parent: S.Schema.Type<typeof UserSchema>, args) => Effect.gen(function* () {
    const db = yield* Database
    return yield* db.getPostsByUserId(parent.id, args.limit)
  })
})
```

**Parameters:**

| Name | Type | Description |
|------|------|-------------|
| `typeName` | `string` | Object type to add field to |
| `fieldName` | `string` | Field name |
| `config.type` | `Schema<A>` | Return type schema |
| `config.args` | `S.Decoder<Args, RArgs>` | Optional whole-argument decoder |
| `config.resolve` | `(parent, args) => Effect<A>` | Resolver receiving parent value |

<Aside type="note">
The parent receives the resolved value of its object type. A separate `.field()`
call cannot infer it from the type-name string: annotate it explicitly, or use
inline `objectType({ fields: ... })` fields for contextual parent inference.
</Aside>

## Directive Methods

### `directive(config)`

Register a custom directive with optional resolver transformation.

```typescript
import { DirectiveLocation } from "graphql"

builder.directive({
  name: "trace",
  locations: [DirectiveLocation.FIELD_DEFINITION],
  args: S.Struct({ label: S.String }),
  description: "Log selected field resolutions",
  apply: ({ label }) => (effect) =>
    Effect.logInfo(label).pipe(Effect.andThen(effect)),
}).query("hello", {
  type: S.String,
  directives: [{ name: "trace", args: { label: "Resolving hello" } }],
  resolve: () => Effect.succeed("world"),
})
```

**Parameters:**

| Name | Type | Description |
|------|------|-------------|
| `config.name` | `string` | Directive name (without `@`) |
| `config.locations` | `DirectiveLocation[]` | Where directive can be used |
| `config.args` | `S.Schema<Args>` | Optional directive argument schema |
| `config.description` | `string` | Directive description |
| `config.apply` | `(args) => (effect) => Effect` | Optional curried resolver wrapper; adds its service requirements |

Registration alone does not execute the wrapper. Apply it to fields using
`directives: [{ name, args }]`. Use `DirectiveLocation` enum members, not raw strings.
`apply` must preserve the wrapped effect's generic error type; put fallible
authorization in the resolver rather than introducing a new typed error here.
Service-dependent wrappers may need explicit `directive<Args, Services>` arguments.

## Building the Schema

### `buildSchema()`

Build the final GraphQL schema.

```typescript
const schema: GraphQLSchema = builder.buildSchema()
```

**Returns:** Standard `GraphQLSchema` from the `graphql` package.

Schema-construction errors may throw. Use GraphQL's `validateSchema(schema)` when
you need an explicit validity check; `buildSchema()` is not a full validation pass.

## Pipe API

The builder implements `Pipeable` for fluent composition:

```typescript
import { GraphQLSchemaBuilder, query, objectType, field } from "@effect-gql/core"

const builder = GraphQLSchemaBuilder.empty.pipe(
  query("users", { ... }),
  objectType({ name: "User", schema: UserSchema }),
  field("User", "posts", { ... })
)
```

See [Pipe Functions](/effect-gql/reference/pipe-functions) for all available functions.

## Type Parameter

The builder tracks service requirements via its type parameter:

```typescript
const builder: GraphQLSchemaBuilder<Database | AuthService> =
  GraphQLSchemaBuilder.empty.pipe(
    query("users", {
      type: S.Array(UserSchema),
      resolve: () => Effect.gen(function* () {
        const db = yield* Database        // Adds Database to R
        const auth = yield* AuthService   // Adds AuthService to R
        // ...
      })
    })
  )
```

`toRouter(builder, layer)` checks accumulated application-service requirements.
`buildSchema()` erases them; `execute(schema, layer)` cannot check that a layer
contains all services for a bare `GraphQLSchema`.

## Example

```typescript
import { GraphQLSchemaBuilder, query, objectType, field, execute } from "@effect-gql/core"
import { Effect, Layer } from "effect"
import * as S from "effect/Schema"

// Define schemas
const UserSchema = S.Struct({
  id: S.String,
  name: S.String,
  email: S.String
})

const PostSchema = S.Struct({
  id: S.String,
  title: S.String,
  authorId: S.String
})

// Build schema
const builder = GraphQLSchemaBuilder.empty.pipe(
  // Register types
  objectType({ name: "User", schema: UserSchema }),
  objectType({ name: "Post", schema: PostSchema }),

  // Root operations
  query("users", {
    type: S.Array(UserSchema),
    resolve: () => Effect.succeed([
      { id: "1", name: "Alice", email: "alice@example.com" }
    ])
  }),

  query("user", {
    type: S.NullOr(UserSchema),
    args: S.Struct({ id: S.String }),
    resolve: ({ id }) => Effect.succeed(
      id === "1" ? { id: "1", name: "Alice", email: "alice@example.com" } : null
    )
  }),

  // Relational fields
  field("User", "posts", {
    type: S.Array(PostSchema),
    resolve: (user: S.Schema.Type<typeof UserSchema>) => Effect.succeed([
      { id: "1", title: "Hello World", authorId: user.id }
    ])
  }),

  field("Post", "author", {
    type: UserSchema,
    resolve: (post: S.Schema.Type<typeof PostSchema>) => Effect.succeed({
      id: post.authorId,
      name: "Alice",
      email: "alice@example.com"
    })
  })
)

// Build and use
const schema = builder.buildSchema()
const result = await Effect.runPromise(
  execute(schema, Layer.empty)(`{
    user(id: "1") { name posts { title author { name } } }
  }`)
)
console.log(JSON.stringify(result, null, 2))
```
