Effect GraphQL provides structured error types that integrate seamlessly with GraphQL's error system and Effect's error channel.

## Built-in Error Types

Effect GraphQL provides several error types out of the box:

```typescript
import {
  GraphQLError,
  ValidationError,
  AuthorizationError,
  NotFoundError,
} from "@effect-gql/core"
```

### GraphQLError

The base error type with support for extensions:

```typescript
new GraphQLError({
  message: "Something went wrong",
  extensions: {
    code: "INTERNAL_ERROR",
    timestamp: new Date().toISOString(),
  },
})
```

### ValidationError

For input validation failures:

```typescript
new ValidationError({
  message: "Invalid email format",
  field: "email",
})
```

### AuthorizationError

For access control violations:

```typescript
new AuthorizationError({
  message: "You don't have permission to access this resource",
})
```

### NotFoundError

For missing resources:

```typescript
new NotFoundError({
  message: "User not found",
  resource: "User",
})
```

Specialized errors carry typed application metadata, not automatic GraphQL
extensions. Their `_tag`, `field`, and `resource` are not serialized to clients.
Use `GraphQLError` with explicit `extensions` when clients need a code or metadata.

## Using Errors in Resolvers

Return errors using `Effect.fail`:

```typescript
.query("user", {
  type: UserSchema,
  args: S.Struct({ id: S.String }),
  resolve: (args) => Effect.gen(function* () {
    const userService = yield* UserService
    const user = yield* userService.getById(args.id)

    if (!user) {
      return yield* Effect.fail(
        new NotFoundError({
          message: `User with id ${args.id} not found`,
          resource: "User",
        })
      )
    }

    return user
  }),
})
```

## Error Transformation

Transform errors as they propagate using Effect combinators:

### Catch Specific Errors

```typescript
resolve: (args) => Effect.gen(function* () {
  const db = yield* DatabaseService
  return yield* db.query(`SELECT * FROM users WHERE id = $1`, [args.id])
}).pipe(
  Effect.catchTag("DatabaseError", (error) =>
    Effect.fail(new GraphQLError({
      message: "Database temporarily unavailable",
      extensions: { code: "SERVICE_UNAVAILABLE" },
    }))
  )
)
```

### Map All Errors

```typescript
resolve: (args) => Effect.gen(function* () {
  // ... resolver logic
}).pipe(
  Effect.mapError((error) => {
    if (error instanceof NotFoundError) {
      return error // Keep as-is
    }
    // Wrap unknown errors
    return new GraphQLError({
      message: "An unexpected error occurred",
      extensions: { code: "INTERNAL_ERROR" },
    })
  })
)
```

### Catch and Recover

```typescript
resolve: (args) => Effect.gen(function* () {
  const cache = yield* CacheService
  return yield* cache.get(args.key)
}).pipe(
  Effect.catch(() =>
    // Fallback to database if cache fails
    Effect.gen(function* () {
      const db = yield* DatabaseService
      return yield* db.get(args.key)
    })
  )
)
```

## Custom Error Types

Create your own error types using Effect's `Data.TaggedError`:

```typescript
import { Data } from "effect"

class RateLimitError extends Data.TaggedError("RateLimitError")<{
  readonly message: string
  readonly retryAfter: number
}> {}

class QuotaExceededError extends Data.TaggedError("QuotaExceededError")<{
  readonly message: string
  readonly quota: number
  readonly used: number
}> {}
```

Use in resolvers:

```typescript
resolve: (args) => Effect.gen(function* () {
  const rateLimiter = yield* RateLimiterService
  const allowed = yield* rateLimiter.check(args.userId)

  if (!allowed.ok) {
    return yield* Effect.fail(
      new RateLimitError({
        message: "Too many requests",
        retryAfter: allowed.retryAfter,
      })
    )
  }

  // Continue with request...
})
```

## Validation Errors

Arguments are decoded automatically using Effect Schema. Decode failures become GraphQL errors, but are not converted to the library's `ValidationError` and have no automatic extension code:

```typescript
.mutation("createUser", {
  type: UserSchema,
  args: S.Struct({
    email: S.String.check(S.isPattern(/@/)),
    age: S.Int.check(S.isGreaterThan(0)),
  }),
  resolve: (args) => {
    // This only runs if validation passes
    return Effect.succeed({ ... })
  },
})
```

For example, passing `age: -5` produces a schema decoding message such as
`Expected a value greater than 0` with a path to `age`. Exact wording is
controlled by Effect Schema; no `extensions.code` or `extensions.field` is added.

## Error Response Format

Errors are formatted according to the GraphQL spec:

```json
{
  "data": { "user": null },
  "errors": [
    {
      "message": "User not found",
      "path": ["user"]
    }
  ]
}
```

This illustrates `NotFoundError({ message: "User not found", resource: "User" })`
on a nullable root field (locations omitted). For a client-visible `NOT_FOUND`
code, instead fail with
`new GraphQLError({ message: "User not found", extensions: { code: "NOT_FOUND" } })`.

## Partial Errors

GraphQL supports partial responses where some fields succeed while others fail:

```typescript
.query("dashboard", {
  type: DashboardSchema,
  resolve: () => Effect.gen(function* () {
    const userService = yield* UserService
    const statsService = yield* StatsService

    // If stats fail, we still want user data
    const [user, stats] = yield* Effect.all([
      userService.getCurrentUser(),
      statsService.getDashboardStats().pipe(
        Effect.catch(() => Effect.succeed(null))
      ),
    ])

    return { user, stats }
  }),
})
```

<Aside type="tip">
  Use `Effect.catch` to return `null` when the output schema allows it.
  `Effect.option` returns an `Option`; unwrap it before returning a nullable value.
</Aside>

## Global Error Handler

When using the HTTP router, you can configure a global error handler for uncaught errors. This handles errors that occur outside of normal GraphQL execution (e.g., malformed requests, server errors).

### Default Behavior

By default, uncaught errors return a 500 Internal Server Error:

```json
{
  "errors": [
    {
      "message": "An error occurred processing your request"
    }
  ]
}
```

In non-production environments, the full error is logged for debugging.

### Custom Error Handler

Provide a custom error handler to control the response:

```typescript
import { makeGraphQLRouter, type ErrorHandler } from "@effect-gql/core/server"
import { HttpServerResponse } from "effect/http"
import { Cause, Effect } from "effect"

const customErrorHandler: ErrorHandler = (cause) =>
  Effect.gen(function* () {
    // Log the error
    yield* Effect.logError("GraphQL request failed", cause)

    // Check for specific error types
    const failure = Cause.findErrorOption(cause)

    if (failure._tag === "Some" && failure.value instanceof RateLimitError) {
      return yield* HttpServerResponse.json(
        {
          errors: [{ message: "Rate limit exceeded", extensions: { code: "RATE_LIMITED" } }],
        },
        { status: 429 }
      )
    }

    // Default error response
    return yield* HttpServerResponse.json(
      {
        errors: [{ message: "Internal server error" }],
      },
      { status: 500 }
    )
  }).pipe(Effect.orDie)

const router = makeGraphQLRouter(schema, serviceLayer, {
  errorHandler: customErrorHandler,
})
```

### Error Handler Type

The error handler receives an Effect `Cause` and must return an `HttpServerResponse`:

```typescript
type ErrorHandler = (
  cause: Cause.Cause<unknown>
) => Effect.Effect<HttpServerResponse.HttpServerResponse, never, never>
```

### When the Error Handler is Called

The global error handler catches failures that escape the HTTP request pipeline,
including malformed JSON, missing required request-body fields, and unexpected
request-processing failures. GraphQL document parse, validation, and resolver
errors are normally returned as GraphQL results instead (including resolver defects).

<Aside type="note">
  Resolver errors that are returned via `Effect.fail()` are handled by GraphQL's normal error system and appear in the response's `errors` array with a 200 status code. The global error handler only catches truly unexpected errors.
</Aside>

### Using the Default Handler

You can import and customize the default handler:

```typescript
import { defaultErrorHandler } from "@effect-gql/core/server"

// Use as-is
const router = makeGraphQLRouter(schema, serviceLayer, {
  errorHandler: defaultErrorHandler,
})

// Or wrap it
const loggingErrorHandler: ErrorHandler = (cause) =>
  Effect.gen(function* () {
    yield* Effect.logError("Unhandled error in GraphQL", cause)
    return yield* defaultErrorHandler(cause)
  })
```

## Best Practices

### 1. Be Specific

Use specific error types rather than generic ones:

```typescript
// Good
new NotFoundError({ message: "User not found", resource: "User" })

// Less helpful
new GraphQLError({ message: "Not found" })
```

### 2. Include Context

Add relevant information to error extensions:

```typescript
new GraphQLError({
  message: "Access denied",
  extensions: {
    code: "FORBIDDEN",
    resource: "admin/users",
    requiredRole: "ADMIN",
    userRole: currentUser.role,
  },
})
```

### 3. Don't Leak Internals

Transform internal errors before returning to clients:

```typescript
Effect.catch((error) =>
  Effect.gen(function* () {
    yield* Effect.logError("Internal error", error)
    return yield* Effect.fail(new GraphQLError({
      message: "An error occurred processing your request",
      extensions: { code: "INTERNAL_ERROR" },
    }))
  })
)
```

### 4. Use Error Boundaries

Create error handling layers for different concerns:

Here `AuthError` and `DatabaseError` are your application's error classes.

```typescript
const withAuthErrors = <A, E, R>(effect: Effect.Effect<A, E, R>) =>
  effect.pipe(
    Effect.mapError((error) =>
      error instanceof AuthError
        ? new AuthorizationError({ message: error.message })
        : error
    )
  )

const withDatabaseErrors = <A, E, R>(effect: Effect.Effect<A, E, R>) =>
  effect.pipe(
    Effect.mapError((error) =>
      error instanceof DatabaseError
        ? new GraphQLError({
            message: "Database error",
            extensions: { code: "DATABASE_ERROR" },
          })
        : error
    )
  )

// Use in resolver
resolve: (args) => myLogic(args).pipe(
  withAuthErrors,
  withDatabaseErrors,
)
```
