title: Middleware
description: Global resolver wrapping for cross-cutting concerns like logging, metrics, and authorization

import { Aside, Steps } from '@astrojs/starlight/components';

Middleware provides a way to wrap resolver execution with cross-cutting concerns. Unlike directives (which are applied explicitly to individual fields), middleware can apply globally or match fields by pattern.

Middleware wraps registered root-operation and computed-field resolvers.
Schema-derived object properties that use GraphQL's default property resolver
are not individually wrapped.

## When to Use Middleware vs Directives

| Feature | Middleware | Directives |
|---------|-----------|------------|
| Scope | Global or pattern-matched | Per-field, explicit |
| Declaration | Registered on builder | Applied in field config |
| Use case | Logging, metrics, auth patterns | Field-specific transformations |
| Execution | Automatic based on match | Only when directive is applied |

## Quick Start

<Steps>
1. **Register middleware on the builder**

   ```typescript
   import { GraphQLSchemaBuilder, middleware } from "@effect-gql/core"

   const builder = GraphQLSchemaBuilder.empty.pipe(
     middleware({
       name: "logging",
       apply: (effect, ctx) =>
         Effect.gen(function* () {
           const field = `${ctx.info.parentType.name}.${ctx.info.fieldName}`
           yield* Effect.logInfo(`Resolving ${field}`)
           return yield* effect
         }),
     }),
   )
   ```

2. **Add your queries and mutations**

   ```typescript
   const schema = builder.pipe(
     query("hello", {
       type: S.String,
       resolve: () => Effect.succeed("world"),
     }),
   ).buildSchema()
   ```

3. **Registered resolvers are automatically wrapped**

   When `{ hello }` is executed, the logging middleware runs automatically.
</Steps>

## Middleware Configuration

### Basic Middleware

The simplest middleware applies to every registered resolver:

```typescript
middleware({
  name: "timing",
  description: "Logs resolver execution time",
  apply: (effect, ctx) =>
    Effect.gen(function* () {
      const start = Date.now()
      const result = yield* effect
      const duration = Date.now() - start
      yield* Effect.logInfo(`${ctx.info.fieldName} took ${duration}ms`)
      return result
    }),
})
```

### Pattern-Matched Middleware

Use the `match` predicate to selectively apply middleware:

```typescript
middleware({
  name: "adminLogging",
  description: "Logs admin-prefixed fields",
  match: (info) => info.fieldName.startsWith("admin"),
  apply: (effect, ctx) => effect.pipe(
    Effect.tap(() => Effect.logInfo(`Resolved ${ctx.info.fieldName}`))
  ),
})
```

The `match` function receives the GraphQL `info` object and returns `true` if middleware should apply.

Middleware's `apply` is polymorphic in the resolver's success and error types:
it must preserve `A` and cannot add a new typed error channel. Put failing
authorization guards in resolvers, where their error types can be accumulated.
The same constraint applies to executable directive transformers. Do not
convert expected authorization failures to defects just to satisfy this signature.

### Middleware with Services

Middleware can depend on Effect services:

```typescript
class MetricsService extends Context.Service<
  MetricsService,
  {
    readonly recordTiming: (field: string, ms: number) => Effect.Effect<void>
  }
>()("MetricsService") {}

middleware<MetricsService>({
  name: "metrics",
  apply: (effect, ctx) =>
    Effect.gen(function* () {
      const metrics = yield* MetricsService
      const field = `${ctx.info.parentType.name}.${ctx.info.fieldName}`
      const start = Date.now()

      const result = yield* effect

      yield* metrics.recordTiming(field, Date.now() - start)
      return result
    }),
})
```

<Aside type="tip">
  The type parameter `<MetricsService>` tells the type system this middleware requires the MetricsService. This requirement is automatically accumulated in the schema builder's type.
</Aside>

## Middleware Context

The `apply` function receives two arguments:

```typescript
interface MiddlewareRegistration<R> {
  apply: <A, E, R2>(
    effect: Effect.Effect<A, E, R2>,
    ctx: MiddlewareContext
  ) => Effect.Effect<A, E, R | R2>
}
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `effect` | `Effect<A, E, R>` | The wrapped resolver effect to execute |
| `ctx.parent` | `unknown` | The parent object (root for queries/mutations) |
| `ctx.args` | `Record<string, unknown>` | The field arguments |
| `ctx.info` | `GraphQLResolveInfo` | Full GraphQL resolve info |

### Using Context Values

```typescript
middleware({
  name: "fieldLogger",
  apply: (effect, ctx) =>
    Effect.gen(function* () {
      yield* Effect.logInfo(`Field: ${ctx.info.fieldName}`)
      yield* Effect.logInfo(`Parent type: ${ctx.info.parentType.name}`)
      yield* Effect.logInfo(`Args: ${JSON.stringify(ctx.args)}`)
      return yield* effect
    }),
})
```

## Execution Order

Middleware executes in "onion" order - first registered is outermost:

```typescript
const trace = (name: string) => <A, E, R>(effect: Effect.Effect<A, E, R>) =>
  Effect.gen(function* () {
    yield* Effect.logInfo(`${name}.before`)
    const result = yield* effect
    yield* Effect.logInfo(`${name}.after`)
    return result
  })

const builder = GraphQLSchemaBuilder.empty.pipe(
  middleware({ name: "outer", apply: trace("outer") }),
  middleware({ name: "middle", apply: trace("middle") }),
  middleware({ name: "inner", apply: trace("inner") }),
)
```

Execution flow:
```
outer.before → middle.before → inner.before → resolver → inner.after → middle.after → outer.after
```

This is the same pattern as Koa middleware or Express middleware chains.

## Common Patterns

### Logging Middleware

```typescript
middleware({
  name: "logging",
  apply: (effect, ctx) =>
    Effect.gen(function* () {
      const field = `${ctx.info.parentType.name}.${ctx.info.fieldName}`
      yield* Effect.logInfo(`[START] ${field}`)
      const start = Date.now()

      const result = yield* effect

      yield* Effect.logInfo(`[END] ${field} (${Date.now() - start}ms)`)
      return result
    }),
})
```

### Error Logging

```typescript
middleware({
  name: "errorLogging",
  apply: (effect, ctx) =>
    effect.pipe(
      Effect.tapError((error) =>
        Effect.logError(`Error in ${ctx.info.parentType.name}.${ctx.info.fieldName}`, error)
      )
    ),
})
```

This preserves the original error type. A middleware cannot replace arbitrary
resolver failures with a new `Error` type; normalize typed failures in resolvers.

### Role-Based Access Control

Keep authorization failures in the resolver's typed channel:

```typescript
query("adminStats", {
  type: StatsSchema,
  resolve: () => Effect.gen(function* () {
    const auth = yield* AuthService
    yield* auth.requireRole("ADMIN")
    const stats = yield* StatsService
    return yield* stats.getData()
  }),
})
```

Use a shared application guard across protected resolvers. Pattern-matched
middleware can observe those fields but cannot add a new authorization error
to every resolver's arbitrary error type.

### Caching and Generic Results

Middleware must also preserve an arbitrary resolver result type `A`. An untyped
cache returning `unknown` cannot satisfy this contract without unsafe casts.
Implement typed value caching in individual resolvers, and use the
[caching guide](/effect-gql/guides/response-caching) for response cache policies.

## Composing with Directives

Middleware and directives can work together. Middleware wraps the entire resolver chain (including directive transformations):

```typescript
const builder = GraphQLSchemaBuilder.empty.pipe(
  // Middleware wraps everything
  middleware({
    name: "timing",
    apply: (effect) => effect.pipe(Effect.tap(() => Effect.logInfo("Resolved"))),
  }),

  // Directive transformers must preserve every possible result type.
  directive({
    name: "logField",
    locations: [DirectiveLocation.FIELD_DEFINITION],
    apply: () => (effect) => effect.pipe(Effect.tap(() => Effect.logInfo("Greeting resolved"))),
  }),

  query("greeting", {
    type: S.String,
    directives: [{ name: "logField" }],
    resolve: () => Effect.succeed("hello"),
  }),
)
```

Execution order: `middleware.before → directive.before → resolver → directive.after → middleware.after`

## Full Example

```typescript
import { Effect, Layer, Context } from "effect"
import * as S from "effect/Schema"
import { GraphQLSchemaBuilder, middleware, query, execute } from "@effect-gql/core"

// Services
class AuthService extends Context.Service<
  AuthService,
  { readonly requireAdmin: () => Effect.Effect<void, Error> }
>()("AuthService") {}

class MetricsService extends Context.Service<
  MetricsService,
  { readonly recordTiming: (field: string, ms: number) => Effect.Effect<void> }
>()("MetricsService") {}

// Build schema with middleware
const builder = GraphQLSchemaBuilder.empty.pipe(
  // Global logging
  middleware({
    name: "logging",
    apply: (effect, ctx) =>
      Effect.gen(function* () {
        yield* Effect.logInfo(`Resolving ${ctx.info.fieldName}`)
        return yield* effect
      }),
  }),

  // Metrics for all fields
  middleware<MetricsService>({
    name: "metrics",
    apply: (effect, ctx) =>
      Effect.gen(function* () {
        const metrics = yield* MetricsService
        const start = Date.now()
        const result = yield* effect
        yield* metrics.recordTiming(ctx.info.fieldName, Date.now() - start)
        return result
      }),
  }),

  // Queries
  query("users", {
    type: S.Array(S.Struct({ id: S.String, name: S.String })),
    resolve: () => Effect.succeed([{ id: "1", name: "Alice" }]),
  }),

  query("adminStats", {
    type: S.Struct({ count: S.Number }),
    resolve: () => Effect.gen(function* () {
      const auth = yield* AuthService
      yield* auth.requireAdmin()
      return { count: 42 }
    }),
  }),
)

const schema = builder.buildSchema()
const serviceLayer = Layer.mergeAll(
  Layer.succeed(AuthService, { requireAdmin: () => Effect.void }),
  Layer.succeed(MetricsService, {
    recordTiming: (field, ms) => Effect.logInfo(`${field}: ${ms}ms`),
  }),
)
const result = await Effect.runPromise(
  execute(schema, serviceLayer)("{ users { name } adminStats { count } }")
)
```
