Effect GQL supports automatic HTTP `Cache-Control` header generation based on field-level cache hints. This enables CDN caching for public queries and browser caching for user-specific data.

## Quick Start

Enable cache control by adding `cacheControl` hints to your fields:

```typescript
import { GraphQLSchemaBuilder, query, objectType, field, toRouter } from "@effect-gql/core"
import { serve } from "@effect-gql/node"
import { Effect, Layer } from "effect"
import * as S from "effect/Schema"

const UserSchema = S.Struct({
  id: S.String,
  name: S.String,
  email: S.String,
})

const builder = GraphQLSchemaBuilder.empty.pipe(
  // Type-level hint: all User fields cache for 1 hour
  objectType({
    name: "User",
    schema: UserSchema,
    cacheControl: { maxAge: 3600 },
  }),

  // Field-level hint: email is private, cache for 1 minute
  field("User", "email", {
    type: S.String,
    cacheControl: { maxAge: 60, scope: "PRIVATE" },
    resolve: (user: typeof UserSchema.Type) => Effect.succeed(user.email),
  }),

  // Query with cache hint
  query("users", {
    type: S.Array(UserSchema),
    cacheControl: { maxAge: 300 },  // 5 minutes
    resolve: () => Effect.succeed([
      { id: "1", name: "Alice", email: "alice@example.com" },
    ]),
  }),
)

const router = toRouter(builder, Layer.empty, {
  cacheControl: { enabled: true },
})

serve(router, Layer.empty, { port: 4000 })
```

## How It Works

### Cache Policy Computation

Effect GQL computes the overall cache policy by analyzing all fields in the query:

1. **maxAge**: Uses the **minimum** maxAge of all resolved fields
2. **scope**: Set to `PRIVATE` if **any** field is `PRIVATE`

```graphql
# Query both public and private data
query {
  users {       # maxAge: 300, PUBLIC
    id          # inherits from User type: 3600
    name        # inherits from User type: 3600
    email       # maxAge: 60, PRIVATE (field override)
  }
}
```

**Result**: `Cache-Control: private, max-age=60`

The response uses `maxAge: 60` (minimum) and `scope: PRIVATE` (any field is private).

### HTTP Headers

Based on the computed policy, Effect GQL sets the `Cache-Control` header:

| Policy | Header |
|--------|--------|
| `maxAge: 0` | `Cache-Control: no-store` |
| `maxAge: 3600, scope: PUBLIC` | `Cache-Control: public, max-age=3600` |
| `maxAge: 60, scope: PRIVATE` | `Cache-Control: private, max-age=60` |

## Cache Hints

### Field-Level Hints

Apply cache hints to individual query or object fields:

```typescript
query("publicData", {
  type: S.String,
  cacheControl: { maxAge: 3600 },  // Cache for 1 hour
  resolve: () => Effect.succeed("data"),
})

field("User", "recommendations", {
  type: S.Array(ProductSchema),
  cacheControl: { maxAge: 300, scope: "PRIVATE" },  // User-specific
  resolve: (user: typeof UserSchema.Type) => getRecommendations(user.id),
})
```

### Type-Level Hints

Apply default cache hints to all fields returning a type:

```typescript
objectType({
  name: "Product",
  schema: ProductSchema,
  cacheControl: { maxAge: 3600 },  // All Product fields cache 1 hour
})
```

Field-level hints override type-level hints.

### Cache Hint Options

```typescript
interface CacheHint {
  // Maximum age in seconds (0 = no cache)
  maxAge?: number

  // PUBLIC: CDN + browser cacheable
  // PRIVATE: Browser only (user-specific)
  scope?: "PUBLIC" | "PRIVATE"

  // Inherit maxAge from parent field
  inheritMaxAge?: boolean
}
```

## Default Behaviors

Effect GQL follows these defaults (matching Apollo Server):

| Field Type | Default maxAge | Behavior |
|------------|---------------|----------|
| Root fields (Query) | 0 | Must opt-in to caching |
| Object-returning fields | 0 | Must opt-in to caching |
| Scalar fields | inherited | Inherits parent's maxAge |
| Introspection fields | ignored | Don't affect cache policy |

<Aside type="caution">
Mutations and subscriptions are excluded from cache control. Only queries receive `Cache-Control` headers.
</Aside>

## Configuration

### Router Options

```typescript
const router = toRouter(builder, layer, {
  cacheControl: {
    // Enable cache control (default: true when cacheControl is set)
    enabled: true,

    // Default maxAge for fields without hints (default: 0)
    defaultMaxAge: 0,

    // Default scope for fields without hints (default: "PUBLIC")
    defaultScope: "PUBLIC",

    // Set HTTP headers on responses (default: true)
    calculateHttpHeaders: true,
  },
})
```

### Environment Variables

```bash
GRAPHQL_CACHE_CONTROL_ENABLED=true
GRAPHQL_CACHE_CONTROL_DEFAULT_MAX_AGE=0
GRAPHQL_CACHE_CONTROL_DEFAULT_SCOPE=PUBLIC
```

## CDN Integration

### With Persisted Queries

Cache control works best with [Persisted Queries](/effect-gql/guides/persisted-queries) and GET requests:

```typescript
import { makePersistedQueriesRouter } from "@effect-gql/persisted-queries"

const router = makePersistedQueriesRouter(schema, layer, {
  mode: "apq",
  enableGet: true,  // Enable GET requests for CDN caching
  cacheHints: builder.getCacheHints(),
  cacheControl: { enabled: true },
})
```

For a public query with `maxAge: 3600`, a persisted GET request can produce:

```
GET /graphql?extensions={"persistedQuery":{"version":1,"sha256Hash":"abc123"}}

Cache-Control: public, max-age=3600
```

Pass `cacheHints` from your builder when creating a persisted-query router from a
GraphQL schema. The router computes the policy for the selected operation on both
GET and POST requests: the shortest field lifetime wins, and any private field
makes the response private. Without cache hints or a positive `defaultMaxAge`,
queries receive `Cache-Control: no-store`.

`cacheControl.enabled: false` or `cacheControl.calculateHttpHeaders: false` omits
these headers. Mutations do not receive cacheable headers, and execution responses
containing GraphQL errors receive `no-store` when header calculation is enabled.

### CDN Configuration
Only cache anonymous, explicitly public GET queries. Keep the entire query string
in the cache key, including `extensions`, `variables`, `operationName`, and any
full `query` text. Include every other response-varying input (for example,
`Origin` for reflected CORS), or make that input constant at the public endpoint.
Do not forward unkeyed identity/tenant headers to a cacheable origin.

**Authenticated and cookie-bearing traffic must bypass shared caches before
cache lookup**, not just on an origin miss. Use an uncached endpoint/behavior for
that traffic, and do not strip credentials to make it look anonymous. Public
endpoints must never personalize results or set cookies. Continue marking
user-specific fields `PRIVATE` (or use `maxAge: 0`); cache hints do not perform
authorization. Private browser caches also need account-change invalidation;
use `no-store` for sensitive data that must not survive logout.

  <TabItem label="Cloudflare">
Cloudflare does not cache GraphQL JSON by default. Create a narrowly scoped
Cache Rule for your anonymous public GET endpoint, retaining the full query
string in the cache key and honoring origin Cache-Control. Add a higher-priority
bypass rule for `Authorization` or any `Cookie` header and all other GraphQL
traffic. Do not use an Edge Cache TTL override that ignores origin `private`,
`no-store`, or `no-cache`, and do not enable caching for responses with
`Set-Cookie`. See Cloudflare's [default cache behavior](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/)
and [origin cache-control guidance](https://developers.cloudflare.com/cache/concepts/cache-control/).
  </TabItem>
  <TabItem label="Fastly">
Configure `pass` before lookup for authenticated/cookie-bearing requests,
non-GET methods, and non-public GraphQL endpoints. Preserve the full URL/query
string cache key. At response time, pass `private`, `no-store`, `no-cache`,
`Set-Cookie`, non-success responses, and responses without explicit positive
public cache lifetime. Keep the origin's parsed TTL rather than extracting
`max-age` with a regex: that can accidentally cache `private, max-age=60`.

Fastly's standard boilerplate handles `private` and `Set-Cookie`, but custom VCL
and fallback TTLs can change these protections. Apply the explicit pass rules
above and do not override them with `Surrogate-Control` or a forced TTL.
See [Fastly's HTTP caching semantics](https://www.fastly.com/documentation/guides/concepts/cache/cache-freshness/).
  </TabItem>
  <TabItem label="AWS CloudFront">
Use a **custom query-aware cache policy** with minimum and default TTLs of zero.
This CloudFormation resource is for a separate anonymous `/graphql/public`
endpoint; configure that path in `makePersistedQueriesRouter` as well:

Use pre-registered/safelist operations on this GET-only behavior; it is not an
APQ registration endpoint.

```yaml
Resources:
  PublicGraphQLCachePolicy:
    Type: AWS::CloudFront::CachePolicy
    Properties:
      CachePolicyConfig:
        Name: PublicGraphQLQueries
        MinTTL: 0
        DefaultTTL: 0
        MaxTTL: 3600
        ParametersInCacheKeyAndForwardedToOrigin:
          EnableAcceptEncodingGzip: true
          EnableAcceptEncodingBrotli: true
          HeadersConfig:
            HeaderBehavior: whitelist
            Headers: [Origin]
          CookiesConfig:
            CookieBehavior: none
          QueryStringsConfig:
            QueryStringBehavior: all
  RejectPublicGraphQLCredentials:
    Type: AWS::CloudFront::Function
    Properties:
      Name: RejectPublicGraphQLCredentials
      AutoPublish: true
      FunctionConfig:
        Comment: Reject credentials before public cache lookup
        Runtime: cloudfront-js-2.0
      FunctionCode: |
        function handler(event) {
          var request = event.request;
          if (request.headers.authorization || Object.keys(request.cookies).length > 0) {
            return {
              statusCode: 403,
              headers: { "cache-control": { value: "no-store" } }
            };
          }
          return request;
        }
```

Attach both resources to the public cache behavior in your distribution
(`GraphQLOrigin` below is the ID of your existing origin):

```yaml
PathPattern: /graphql/public
TargetOriginId: GraphQLOrigin
ViewerProtocolPolicy: https-only
AllowedMethods: [GET, HEAD, OPTIONS]
CachedMethods: [GET, HEAD]
CachePolicyId: !Ref PublicGraphQLCachePolicy
FunctionAssociations:
  - EventType: viewer-request
    FunctionARN: !GetAtt RejectPublicGraphQLCredentials.FunctionMetadata.FunctionARN
```

The viewer-request function rejects credentials **even on cache hits**. If your
application uses other identity headers, reject those too. Send authenticated
and cookie-bearing requests to a separate uncached `/graphql` behavior with
minimum/default/maximum TTLs all `0`, forwarding authorization, cookies, and all
GraphQL query parameters to the origin. An origin-request policy forwards values;
it does not make them part of a public cache key. Do not share this public policy
with an authenticated route.

AWS documents that [a minimum TTL above zero overrides `private` and `no-store`](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/Expiration.html).
`MinTTL: 0` respects those directives, while `DefaultTTL: 0` avoids caching
responses that omit a lifetime. The managed
[`CachingOptimized` policy](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/using-managed-cache-policies.html#managed-cache-caching-optimized)
is not suitable: it ignores query strings and has a positive minimum TTL.
See the [cache-policy specification](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-properties-cloudfront-cachepolicy-cachepolicyconfig.html),
[cache-key parameters](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-properties-cloudfront-cachepolicy-parametersincachekeyandforwardedtoorigin.html),
[function request/cookie structure](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/functions-event-structure.html),
and [authorization-forwarding warning](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/add-origin-custom-headers.html#add-origin-custom-headers-forward-authorization).
  </TabItem>

## Programmatic Access

### Computing Cache Policy Manually

```typescript
import { computeCachePolicyFromQuery, toCacheControlHeader } from "@effect-gql/core/server"

const policy = await Effect.runPromise(
  computeCachePolicyFromQuery(
    "{ users { id name } }",
    undefined,  // operationName
    schema,
    builder.getCacheHints(),
    { defaultMaxAge: 0 }
  )
)

console.log(policy)  // { maxAge: 300, scope: "PUBLIC" }
console.log(toCacheControlHeader(policy))  // "public, max-age=300"
```

### Getting Cache Hints from Builder

```typescript
const hints = builder.getCacheHints()
// Map<string, CacheHint>
// "Query.users" -> { maxAge: 300 }
// "User" -> { maxAge: 3600 }
// "User.email" -> { maxAge: 60, scope: "PRIVATE" }
```

## Best Practices

### 1. Start with No Caching

Default to `maxAge: 0` and explicitly opt-in to caching:

```typescript
// Only cache fields you've verified are safe
query("publicPosts", {
  type: S.Array(PostSchema),
  cacheControl: { maxAge: 300 },  // Explicitly enable
  resolve: () => getPosts(),
})
```

### 2. Mark User-Specific Data as Private

```typescript
query("me", {
  type: UserSchema,
  cacheControl: { maxAge: 60, scope: "PRIVATE" },
  resolve: () => getCurrentUser(),
})

field("User", "settings", {
  type: SettingsSchema,
  cacheControl: { scope: "PRIVATE" },  // Even with inheritance
  resolve: (user: typeof UserSchema.Type) => getSettings(user.id),
})
```

### 3. Use Type-Level Hints for Consistency

```typescript
// All Product data is public and stable
objectType({
  name: "Product",
  schema: ProductSchema,
  cacheControl: { maxAge: 3600 },
})

// Override only for dynamic fields
field("Product", "inventory", {
  type: S.Number,
  cacheControl: { maxAge: 60 },  // More volatile
  resolve: (product: typeof ProductSchema.Type) => getInventory(product.id),
})
```

### 4. Combine with Complexity Limiting

```typescript
const router = toRouter(builder, layer, {
  complexity: { maxComplexity: 1000 },
  cacheControl: { enabled: true },
})
```

## API Reference

### Types

| Export | Description |
|--------|-------------|
| `CacheHint` | Cache hint with `maxAge`, `scope`, `inheritMaxAge` |
| `CacheControlScope` | `"PUBLIC"` or `"PRIVATE"` |
| `CachePolicy` | Computed policy with `maxAge` and `scope` |
| `CacheHintMap` | Map of type/field names to cache hints |
| `CacheControlConfig` | Router configuration options |

### Functions

| Export | Description |
|--------|-------------|
| `computeCachePolicy(info)` | Compute cache policy from parsed query |
| `computeCachePolicyFromQuery(query, ...)` | Compute cache policy from query string |
| `toCacheControlHeader(policy)` | Convert policy to HTTP header value |

### Configuration

| Export | Description |
|--------|-------------|
| `CacheControlConfigFromEnv` | Effect Config for environment variables |
