The `GraphQLSchemaBuilder` is the core API for constructing GraphQL schemas in Effect GraphQL. It provides an immutable, pipeable interface that accumulates type information as you build.

## Getting Started

```typescript
import { GraphQLSchemaBuilder } from "@effect-gql/core"

// Start with an empty builder
const builder = GraphQLSchemaBuilder.empty

// Build your schema
const schema = builder
  .query("hello", { type: S.String, resolve: () => Effect.succeed("world") })
  .buildSchema()
```

## Immutability

Every method returns a **new builder instance**. This enables safe composition:

```typescript
const base = GraphQLSchemaBuilder.empty
  .objectType({ name: "User", schema: UserSchema })

// Create different schemas from the same base
const simpleSchema = base
  .query("users", { ... })
  .buildSchema()

const fullSchema = base
  .query("users", { ... })
  .mutation("createUser", { ... })
  .buildSchema()
```

## Pipe API

For a more functional style, use the standalone functions with `.pipe()`:

```typescript
import {
  query,
  mutation,
  objectType,
  field,
  compose,
} from "@effect-gql/core"

const schema = GraphQLSchemaBuilder.empty.pipe(
  objectType({ name: "User", schema: UserSchema }),
  query("users", { type: S.Array(UserSchema), resolve: () => Effect.succeed([]) }),
  mutation("createUser", { type: UserSchema, args: CreateUserInput, resolve: ... }),
).buildSchema()
```

### Composing Builders

Use `compose` to combine multiple operations:

```typescript
const withUserTypes = compose(
  objectType({ name: "User", schema: UserSchema }),
  objectType({ name: "Post", schema: PostSchema }),
)

const withQueries = compose(
  query("users", { ... }),
  query("posts", { ... }),
)

const schema = GraphQLSchemaBuilder.empty.pipe(
  withUserTypes,
  withQueries,
).buildSchema()
```

`compose` preserves the services required by every operation, including argument
decoders, and retains services already required by its input builder. This also
applies to nested composition and arrays passed with `compose(...operations)`.
`compose()` with no operations leaves the builder unchanged. Pass the resulting
builder to `toRouter` with a layer providing all accumulated services.

Built-in operations and `compose` return the public `SchemaOperation<R>` type,
available from both `@effect-gql/core` and `@effect-gql/core/builder`. Reusable
operations can be exported with inferred types, including from libraries that
emit TypeScript declarations:

```typescript
export const withGreeting = query("hello", {
  type: S.String,
  resolve: () => Effect.succeed("world"),
})
export const withGreetingQueries = compose(withGreeting)
```

Custom generic operations are supported without annotations:

```typescript
const withHello = <R>(builder: GraphQLSchemaBuilder<R>) =>
  builder.query("hello", {
    type: S.String,
    resolve: () => Effect.succeed("world"),
  })

const withGreetings = compose(withHello)
```

Calls infer up to 20 custom operations independently. For dynamically sized,
heterogeneous arrays of custom operations, normalize each with `compose(custom)`
before combining them; built-in and already-composed operation arrays retain their
individual requirements without an arity limit:

```typescript
const operations = [compose(withHello), compose(withServiceQueries)]
const withOperations = compose(...operations)
```

## Object Types

### Basic Registration

```typescript
const UserSchema = S.Struct({
  id: S.String,
  name: S.String,
  email: S.String,
})

builder.objectType({ name: "User", schema: UserSchema })
```

### Name Inference

With `S.TaggedStruct` or `S.Class`, names are inferred automatically:

```typescript
const UserSchema = S.TaggedStruct("User", {
  id: S.String,
  name: S.String,
})

// Name "User" is inferred
builder.objectType({ schema: UserSchema })
```

### With Computed Fields

Add fields with resolvers inline:

```typescript
builder.objectType({
  name: "User",
  schema: UserSchema,
  fields: {
    fullName: {
      type: S.String,
      resolve: (parent) => Effect.succeed(
        `${parent.firstName} ${parent.lastName}`
      ),
    },
    posts: {
      type: S.Array(PostSchema),
      args: S.Struct({ limit: S.optional(S.Int) }),
      resolve: (parent, args) => Effect.gen(function* () {
        const postService = yield* PostService
        return yield* postService.getByAuthor(parent.id, args.limit)
      }),
    },
  },
})
```

Each inline field contributes its own resolver and argument-decoder service
requirements. `objectType` unions these requirements across all fields and keeps
services already required by the builder, for both the method and pipe APIs.
The resolver's `parent` is contextually typed from the registered schema; pure
fields and empty `fields` add no services. Provide a layer containing the complete
union when passing the builder to `toRouter`.

Typed maps with optional fields, including `Partial<Record<...>>`, follow the
same rules. Optional-property absence adds no service requirement; each declared
field still contributes its resolver and argument-decoder services when the
field itself requires them. Pure optional fields remain compatible with
`Layer.empty`, whether present or omitted.

Reusable union-typed field maps and individual field configurations preserve
requirements from every branch, including branches with no `args` and maps with
different field names. The supplied layer must cover every possible branch.
Generic wrappers can name the inferred requirement type with
`ObjectFieldsServices<Fields>`, exported from both `@effect-gql/core` and
`@effect-gql/core/builder`.

Registered object and interface types also survive `S.optionalKey`, `S.mutableKey`,
and combinations of those modifiers, including structs and unencoded primitive
schemas with computed fields. Unregistered key variants reuse the named
registration; optional keys remain nullable without losing that type.
If a base schema and a key-modified schema are explicitly registered under
different names, each exact registration takes precedence over generated key
aliases regardless of registration order. Root fields, nested references, and
registered union member matching retain those distinct names even when the
schemas share the same structural body.

The same precedence applies when a transforming schema and `S.toType(schema)`
have separate registrations. An unregistered wrapper such as
`S.Struct({ value: schema })` retains the original registration's computed fields,
while `S.toType(wrapper)` uses the projected registration's fields. Both wrappers
can appear in the same GraphQL schema, in either conversion order. Generated
object reuse distinguishes their original and projected identities, while harmless
key modifiers and recursive references still reuse the corresponding object type.
Equivalent decoded schemas and their projections still share generated named
types when their reachable output fields resolve identically, so named fragments
remain valid across both forms.

### Adding Fields Separately

Use `.field()` to add fields after type registration:

```typescript
builder
  .objectType({ name: "User", schema: UserSchema })
  .field("User", "posts", {
    type: S.Array(PostSchema),
    resolve: (parent) => Effect.succeed([]),
  })
```

## Root Operations

### Queries

```typescript
// Simple query
.query("hello", {
  type: S.String,
  resolve: () => Effect.succeed("world"),
})

// With arguments
.query("user", {
  type: UserSchema,
  args: S.Struct({ id: S.String }),
  resolve: (args) => Effect.succeed({ id: args.id, name: "Alice" }),
})

// With description
.query("users", {
  type: S.Array(UserSchema),
  description: "Get all users in the system",
  resolve: () => Effect.succeed([]),
})
```

### Mutations

```typescript
.mutation("createUser", {
  type: UserSchema,
  args: S.Struct({
    name: S.String,
    email: S.String,
  }),
  resolve: (args) => Effect.gen(function* () {
    const userService = yield* UserService
    return yield* userService.create(args.name, args.email)
  }),
})
```

### Subscriptions

Subscriptions return an Effect that produces a Stream:

```typescript
import { Stream } from "effect"

.subscription("userCreated", {
  type: UserSchema,
  subscribe: () => Effect.gen(function* () {
    const events = yield* EventService
    return events.userCreatedStream()
  }),
})
```

## Enums

Register enum types with values:

```typescript
.enumType({
  name: "UserStatus",
  values: ["ACTIVE", "INACTIVE", "PENDING"],
  description: "User account status",
})
```

Use in queries with `S.Literal`:

```typescript
.query("usersByStatus", {
  type: S.Array(UserSchema),
  args: S.Struct({
    status: S.Literals(["ACTIVE", "INACTIVE", "PENDING"]),
  }),
  resolve: (args) => Effect.succeed([]),
})
```

## Interfaces

```typescript
const NodeSchema = S.Struct({ id: S.String })

builder
  .interfaceType({ name: "Node", schema: NodeSchema })
  .objectType({
    name: "User",
    schema: UserSchema,
    implements: ["Node"],
  })
```

## Unions

```typescript
const TextSchema = S.TaggedStruct("Text", { body: S.String })
const ImageSchema = S.TaggedStruct("Image", { url: S.String })

builder
  .objectType({ schema: TextSchema })
  .objectType({ schema: ImageSchema })
  .unionType({
    name: "Content",
    types: ["Text", "Image"],
  })
```

## Input Types

Register input types for complex arguments:

```typescript
const CreateUserInput = S.Struct({
  name: S.String,
  email: S.String,
  role: S.optional(S.Literals(["USER", "ADMIN"])),
})

builder
  .inputType({ name: "CreateUserInput", schema: CreateUserInput })
  .mutation("createUser", {
    type: UserSchema,
    args: S.Struct({ input: CreateUserInput }),
    resolve: (args) => Effect.succeed({ id: "1", ...args.input }),
  })
```

Input registrations follow the same exact-schema precedence. For example,
registering `Base` as `BaseInput` and `S.optionalKey(Base)` as `KeyInput` keeps
both names distinct in arguments and nested input fields, in either registration
order. Declare variables using the name registered for the argument's schema:
`BaseInput!` for a required `Base` argument and `KeyInput` for the optional key
variant. Without an explicit registration for a key variant, it reuses the
base schema's registered input name.

GraphQL has no input union type. Unless a union exactly matches a registered
enum, input mapping falls back to its first non-null member. Registered input
objects retain their registered name and identity through that fallback.
Tagged inputs omit `_tag` from GraphQL and restore its encoded literal before
Effect decoding, including when the codec transforms it to a different domain tag.

## Directives

Register custom directives:

```typescript
import { DirectiveLocation } from "graphql"

builder.directive({
  name: "auth",
  description: "Requires authentication",
  locations: [DirectiveLocation.FIELD_DEFINITION],
  args: S.Struct({
    role: S.optional(S.Literals(["USER", "ADMIN"])),
  }),
  transformer: (effect, args) =>
    Effect.gen(function* () {
      const auth = yield* AuthService
      yield* auth.requireRole(args.role ?? "USER")
      return yield* effect
    }),
})
```

## Building the Schema

Call `.buildSchema()` to produce the final `GraphQLSchema`:

```typescript
const schema = builder.buildSchema()

// Use with any GraphQL server
import { graphql } from "graphql"
const result = await graphql({ schema, source: "{ hello }" })
```

<Aside type="tip">
  For request execution with Effect services, use the `execute` function instead of `graphql()` directly.
  See the [Resolvers guide](/effect-gql/guides/resolvers/) for details.
</Aside>
