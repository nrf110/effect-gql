Resolvers in Effect GraphQL are Effect programs. This gives you type-safe error handling, dependency injection, and composability out of the box.

## Basic Resolvers

A resolver is a function that returns an `Effect`:

```typescript
import { Effect } from "effect"
import * as S from "effect/Schema"

.query("hello", {
  type: S.String,
  resolve: () => Effect.succeed("world"),
})
```

### With Arguments

Arguments are decoded and validated with the entire Effect Schema before the resolver runs:

```typescript
.query("greet", {
  type: S.String,
  args: S.Struct({ name: S.String }),
  resolve: (args) => Effect.succeed(`Hello, ${args.name}!`),
})
```

The `args` object is fully typed based on the **decoded** schema. GraphQL inputs use the schema's encoded representation, while resolvers receive its decoded values, including transformations and decoding defaults:

```typescript
.query("double", {
  type: S.Number,
  args: S.Struct({ amount: S.NumberFromString }),
  resolve: ({ amount }) => Effect.succeed(amount + amount),
})
```

The GraphQL query `{ double(amount: "21") }` returns `42`, not `"2121"`.

This decoding applies to query, mutation, and object-field resolvers, as well as subscription `subscribe` and custom `resolve` callbacks. A subscription decodes its arguments **once when the operation starts**: every event's custom resolver and middleware receives that operation's same decoded argument object. Decoding defaults and transformations do not run again for each event. Concurrent subscriptions may share services and documents, but each must use a **fresh operation-context object**. The built-in transports handle this automatically; direct callers must follow the [native subscription context contract](/guides/subscriptions/#native-graphql-subscriptions).

Middleware receives the same decoded arguments as the callback it wraps. Decoders run with the request's services, so effectful schema transformations can use request-scoped dependencies. Invalid inputs produce GraphQL errors without invoking the callback. Fields without an `args` schema skip decoding.

For subscription events, `info.rootValue` is the original emitted payload throughout GraphQL execution: middleware `match(info)` and `apply(effect, context)`, nested computed fields, native GraphQL resolvers, and abstract-type callbacks all see that same root. Object payload identity is preserved, even when the custom subscription resolver transforms the value used as nested fields' parent. Primitive, null, and undefined payloads are not wrapped. Subscription setup middleware still sees the operation's initial root value, before any events are emitted.

Async resolver wrappers may delay or reorder event resolution without changing which decoded arguments an operation receives. They must forward the same operation context to the wrapped resolver. Arguments are associated with that context, not the payload, document, or event timing.

`S.Option(inner)` inputs use GraphQL's nullable representation, not an Effect `Option` object. A supplied value is decoded through `inner` and delivered as `Option.some(value)`; `null` or an omitted required Option argument becomes `Option.none()`. This also works inside nested objects, lists, classes, and recursive inputs. Codecs such as `S.OptionFromNullOr(inner)` retain their existing null encoding rather than being wrapped twice. Genuinely optional keys remain absent when omitted, so schema decoding defaults and optional-key codecs keep their normal behavior.

Tagged schemas keep their literal `_tag` discriminators even though GraphQL does not expose those fields as inputs. The framework restores those encoded discriminator literals before decoding, including inside Option values. All normalized inputs still pass through the entire argument schema's validation and transformations before any typed callback runs.

### Field Resolvers

Field resolvers on object types receive the parent value:

```typescript
.field("User", "fullName", {
  type: S.String,
  resolve: (parent) => Effect.succeed(
    `${parent.firstName} ${parent.lastName}`
  ),
})
```

With arguments:

```typescript
.field("User", "posts", {
  type: S.Array(PostSchema),
  args: S.Struct({
    limit: S.optional(S.Int),
    offset: S.optional(S.Int),
  }),
  resolve: (parent, args) => Effect.succeed(
    posts
      .filter(p => p.authorId === parent.id)
      .slice(args.offset ?? 0, args.limit)
  ),
})
```

## Service Injection

The real power of Effect resolvers is service injection. Define services with Effect's `Context.Service`:

```typescript
import { Context, Layer } from "effect"

// Define a service interface
class UserService extends Context.Service<
  UserService,
  {
    readonly getAll: () => Effect.Effect<User[]>
    readonly getById: (id: string) => Effect.Effect<User | null>
    readonly create: (name: string, email: string) => Effect.Effect<User>
  }
>()("UserService") {}
```

Use services in resolvers with `Effect.gen`:

```typescript
.query("users", {
  type: S.Array(UserSchema),
  resolve: () => Effect.gen(function* () {
    const userService = yield* UserService
    return yield* userService.getAll()
  }),
})

.mutation("createUser", {
  type: UserSchema,
  args: S.Struct({ name: S.String, email: S.String }),
  resolve: (args) => Effect.gen(function* () {
    const userService = yield* UserService
    return yield* userService.create(args.name, args.email)
  }),
})
```

### Providing Services

Services are provided when executing queries via a Layer:

```typescript
import { execute } from "@effect-gql/core"

// Create service implementation
const UserServiceLive = Layer.succeed(UserService, {
  getAll: () => Effect.succeed(users),
  getById: (id) => Effect.succeed(users.find(u => u.id === id) ?? null),
  create: (name, email) => Effect.succeed({ id: generateId(), name, email }),
})

// Compose all services
const AppLayer = Layer.merge(UserServiceLive, PostServiceLive)

// Execute with services
const result = await Effect.runPromise(
  execute(schema, AppLayer)(`
    query {
      users { id name }
    }
  `)
)
```

<Aside>
  The builder's type parameter `R` accumulates all service requirements as you add resolvers.
  TypeScript will error if you forget to provide a required service at execution time.
</Aside>

## Effect Composition

Since resolvers are Effects, you can use all Effect combinators:

### Sequential Operations

```typescript
resolve: (args) => Effect.gen(function* () {
  const userService = yield* UserService
  const user = yield* userService.getById(args.id)

  if (!user) {
    return yield* Effect.fail(new NotFoundError({ message: "User not found" }))
  }

  const postService = yield* PostService
  const posts = yield* postService.getByAuthor(user.id)

  return { ...user, posts }
})
```

### Parallel Operations

```typescript
resolve: () => Effect.gen(function* () {
  const userService = yield* UserService
  const postService = yield* PostService

  // Fetch in parallel
  const [users, posts] = yield* Effect.all([
    userService.getAll(),
    postService.getAll(),
  ], { concurrency: "unbounded" })

  return { users, posts }
})
```

### Error Handling

```typescript
resolve: (args) => Effect.gen(function* () {
  const userService = yield* UserService
  const user = yield* userService.getById(args.id)

  if (!user) {
    return yield* Effect.fail(
      new NotFoundError({ message: `User ${args.id} not found` })
    )
  }

  return user
}).pipe(
  Effect.catchTag("DatabaseError", (e) =>
    Effect.fail(new GraphQLError({ message: "Database unavailable" }))
  )
)
```

## The Execute Function

The `execute` function bridges Effect resolvers with GraphQL execution:

```typescript
import { execute } from "@effect-gql/core"

const runQuery = execute(schema, serviceLayer)

// Execute a query
const result = await Effect.runPromise(
  runQuery(
    `query GetUser($id: String!) { user(id: $id) { name } }`,
    { id: "123" },  // variables
    "GetUser"       // operation name (optional)
  )
)
```

### How It Works

1. Builds an Effect service context from your Layer
2. Passes the services to GraphQL via context
3. Each resolver runs its Effect with those services
4. Services are available throughout the request

```typescript
// Simplified internal flow
execute(schema, layer)(query, variables) =>
  Effect.gen(function* () {
    const services = yield* Effect.context<R>()
    const result = yield* Effect.promise(() =>
      graphql({
        schema,
        source: query,
        variableValues: variables,
        contextValue: { services },
      })
    )
    return result
  }).pipe(Effect.provide(layer))
```

## Request Context

Access request-scoped data using `GraphQLRequestContext`:

```typescript
import { GraphQLRequestContext, makeRequestContextLayer } from "@effect-gql/core"

.query("me", {
  type: UserSchema,
  resolve: () => Effect.gen(function* () {
    const ctx = yield* GraphQLRequestContext
    const authHeader = ctx.request.headers["authorization"]

    // Extract user from token...
    const userId = parseToken(authHeader)

    const userService = yield* UserService
    return yield* userService.getById(userId)
  }),
})
```

Create the request context layer at request time:

```typescript
const requestLayer = makeRequestContextLayer({
  request: {
    headers: req.headers,
    query: req.body.query,
    variables: req.body.variables,
  },
})

const fullLayer = Layer.merge(requestLayer, AppLayer)

execute(schema, fullLayer)(query, variables)
```

## Type Safety

The builder tracks service requirements in its type parameter:

```typescript
// Type: GraphQLSchemaBuilder<never>
const empty = GraphQLSchemaBuilder.empty

// Type: GraphQLSchemaBuilder<UserService>
const withUserQuery = empty.query("users", {
  type: S.Array(UserSchema),
  resolve: () => Effect.gen(function* () {
    const userService = yield* UserService
    return yield* userService.getAll()
  }),
})

// Type: GraphQLSchemaBuilder<UserService | PostService>
const withBoth = withUserQuery.query("posts", {
  type: S.Array(PostSchema),
  resolve: () => Effect.gen(function* () {
    const postService = yield* PostService
    return yield* postService.getAll()
  }),
})
```

When you call `execute(schema, layer)`, TypeScript verifies that `layer` provides all required services.
